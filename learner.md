# Answers to the questions.

## How does Brad describe a Git repository when explaining Git in simple terms?
He describes it as a digital filing cabinet that stores all your files and the changes you've made to them. He also compares it to a time machine for your code, because you can go back to previous versions.
## Why does he recommend learning Git from the terminal before relying on graphical tools?
Because it is powerful and it helps you understand what Git is actually doing behind the scenes. Graphical tools perform the same Git operations, but hide the commands from you. Learning the terminal first also means you won't be lost if a graphical tool isn't available.
## What are the four stages/locations in the Git workflow?
Working Directory: where you make changes to your files.
Staging Area: where you prepare changes before committing.
Local Repository: where Git stores your committed changes.
Remote Repository: where the project is stored remotely, such as GitHub.

## When his local main does not yet contain the merged change, what does he do to bring the latest changes down?
He runs: git pull.
This downloads the latest changes from the remote repository and updates his local branch.
